# Financipz · Backend

FastAPI + SQLAlchemy 2 + Alembic on PostgreSQL.

## Setup

```bash
cd backend
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements-dev.txt
cp .env.example .env   # then fill in the values locally
```

## Run

```bash
uvicorn app.main:app --reload
```

Health check: `GET http://127.0.0.1:8000/api/v1/health`. The `database` field is `ok`, `unreachable`, or `not_configured`.

## Test

```bash
pytest
```

## Authentication

Protected routes require `Authorization: Bearer <access token>`. Tokens are verified with the authentication provider's public keys (ES256 or RS256, no shared secret), checking signature, expiration, issuer and audience. Set `SUPABASE_URL` in `.env`; without it, protected routes answer `503` instead of letting requests through.

`ALLOWED_USER_IDS` and/or `ALLOWED_USER_EMAILS` say who may use the API. If both are empty, protected routes answer `503` instead of accepting any valid account. Add `Depends(get_current_user)` (from `app.core.auth`) to any route that needs a user.

## Database migrations

```bash
alembic upgrade head                              # apply all migrations
alembic revision --autogenerate -m "describe it"  # create a migration from app/db/models.py
alembic downgrade -1                              # undo the last migration
```

Always review an autogenerated migration before applying it. Every new table must enable row level security in its migration.

## Importing a MyFinance backup

```bash
python -m app.importers.myfinance --backup FILE --mapping mapping.json --since 2026-09-01          # simulation
python -m app.importers.myfinance --backup FILE --mapping mapping.json --since 2026-09-01 --apply  # saves
```

Only the movements from `--since` on are imported. Each account opens with the balance it had the day before, so the final balances equal the ones in the backup; if any does not match, nothing is saved. Running it again does not duplicate anything. The mapping file says which backup account becomes which account (name, type, key, identifiers, categories to rename) and which backup movements were manual balance corrections, which are imported as balance adjustments so they do not count in the cash flow. A movement can also be listed as absorbed: it is not imported, and its effect is folded into the opening balance of its account, so the final balance still matches. A deposit on a credit card has no source account in the backup, so it must be listed as one or the other; otherwise the import refuses to run. It holds personal data: keep it out of the repository.

## Notes

- Secrets go only in `backend/.env`, which is gitignored. Never commit real values.
- Accounts are archived, never deleted (foreign keys do not cascade).
